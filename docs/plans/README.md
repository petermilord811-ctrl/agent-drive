# docs/plans/ — design notes & roadmap (maintainer-owned)

Why the kit is built the way it is, and where it's going. These are **reference notes, not a contribution
area** — they explain the design behind the tools and the protocol so a maintainer (or a curious reader)
has the rationale in one place.

- `roadmap.md` — what's next.
- The other notes each cover one design area (progress to viewers, session-chat comms, using
  ScreenMirror's own features, concurrency & control, confirming dangerous actions, missions — the big plan
  a job is done by — and the board: the panel as the room's control surface).

If you're here to **add a task recipe**, you want [`../../skills/`](../../skills/README.md) instead —
that's the growth area, and it takes additive, conflict-free contributions. See
[`../CONTRIBUTING.md`](../../CONTRIBUTING.md).
